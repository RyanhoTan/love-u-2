# Phase 21 context

移动端 `loadAnniversaries` 在请求失败时调用 `setAnniversaries([])`，只显示一次 toast。页面依据 `anniversaries.length === 0` 渲染“还没有纪念日”，因此持续可见的页面错误地把读取失败解释为无数据。应由独立错误状态控制渲染，重试后再根据真实响应进入空列表或卡片状态。

现在使用 `loadError` 与 `isLoading` 优先于列表长度决定状态视图；请求失败保留错误文案和重试按钮，成功后清除错误，只有成功返回空数组时才显示“还没有纪念日”。读取失败不再发一次性 toast 后伪装为空数据。顶部尚未实现的“编辑”入口未纳入本阶段，应继续补真实编辑/删除能力或隐藏入口。
