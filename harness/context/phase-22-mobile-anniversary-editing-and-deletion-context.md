# Phase 22 context

移动端 `app/app/home/anniversary/index.tsx` 顶栏“编辑”只调用 `toast.info("编辑功能开发中")`，纪念日卡片没有打开详情的行为。服务端 PATCH/DELETE 路由已实现当前关系授权；Web 已有可编辑页面与确认删除流程。移动端 API 当前只有 GET/POST，因此本阶段只需补客户端契约和界面，不需改变服务端。

编辑页通过 `getAnniversaries()` 在当前关系授权范围读取并匹配 id，保持服务端列表为单一数据源。PATCH 为全量请求体；未编辑的 `reminderDaysBefore` 原样保留，防止将未知历史值静默归一化。删除前用原生 Alert 确认，成功后返回；失败留在编辑页。无数据库/真机环境，端到端和授权失败行为需后续集成验证。

已添加 `/home/anniversary/[id]/edit` 表单路由，包含标题、分类、原始日期、重复方式和提醒计划编辑。列表焦点恢复后重新拉取数据；因此 PATCH/DELETE 成功返回时，返回列表会刷新。提醒字段默认原样保留；只有用户主动选择计划才转换为当天/3/7 天，页面说明当前不会实际发送通知。服务端 PATCH 为完整替换，所以提交全部字段。
