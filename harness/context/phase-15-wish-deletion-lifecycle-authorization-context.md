# Phase 15 context

心愿 PATCH 的最终 UPDATE 已再次检查心愿所属关系仍为 bound，且当前用户仍是该关系一方；个人心愿写入还要求用户当前没有 bound 关系。三个删除生命周期 handler 只有先调用 `findWishById`，之后按 `id` 和删除状态执行写入。两条请求之间若关系或行状态改变，后者可继续修改并错误地返回成功。

本阶段只复用已有写入政策。解绑后的共同数据如何归属仍是 PRD 第 12 节待决问题，不在这里推断或改变读取范围。没有授权访问真实数据库，无法验证 MySQL 并发时序；需在后续隔离集成测试中覆盖。

写入 SQL 的授权条件从 PATCH 提取为统一函数，情侣心愿要求相同 `relationship_id`、关系仍为 `bound` 且请求者是关系一方；个人心愿要求 `relationship_id IS NULL`、本人创建且当前没有 bound 关系。三个删除生命周期 handler 继续先查心愿以维持原响应，再在 UPDATE/DELETE 同一语句中重验授权及删除状态；受影响行数为 0 时返回 404。用户已解绑或转为其他关系、心愿状态已被另一请求改变时，不会因预查成功而假报删除/恢复成功。

静态检查不能取代真实 MySQL 并发测试；尤其 MySQL 事务隔离下关系变更与子查询的精确时序，需要隔离测试库验证。另一个相邻缺口是 `createWishRecord` 在预查后 INSERT 没有同语句授权，应独立阶段处理。
