# Phase 20 context

纪念日 API 仅持久化 `reminder_days_before`，未发现基于该字段的定时投递、设备 token 或账户级通知偏好闭环。但移动端创建页提供“提前 X 天提醒”开关，Web 多处写有“会轻轻提醒双方”“当天早上出现在首页”“相关提醒取消”等确定性承诺。PRD-DAY-001 明确要求：无通知能力时不得声称提醒生效。

本阶段只修正用户可见的承诺，保留现有偏好字段和提交行为，避免静默修改已有值。多开关与单一 `reminderDaysBefore` 字段的映射不完全一致；后续需要独立整理输入控件与数据语义，不能把文案修复当作提醒功能上线。

移动端在提醒选择旁明确显示“当前不会发送提醒”；Web 在表单旁说明仅保存计划，并去除首页、列表、重复说明及删除确认里的实际通知承诺。Web 删除仍是服务端逻辑删除，页面没有恢复入口，因此文案改为“从列表移除，当前没有恢复入口”，不再称数据库永久删除。现有提醒天数值与请求形状不变。
